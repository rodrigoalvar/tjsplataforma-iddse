Configuración del Sistema

Gestiona los parámetros de base de datos, servidor PACS, URLs y otras configuraciones del sistema

Nota: Los cambios en la configuración de base de datos se guardan en la tabla configuracion de la base de datos actual. El sistema leerá estos valores automáticamente. Si deseas que estos valores sean los predeterminados para nuevas instalaciones, también puedes actualizar el archivo config/database.php.

Nota: Los cambios en la configuración de PACS se guardan en la base de datos y se aplican automáticamente. El sistema recargará la configuración desde la base de datos al iniciar.

Study routing: define si los enlaces de Ver y Descargar usan el PACS local o R2 (manifest / ZIP presignado). Requiere R2 habilitado en Cloud Storage y permisos study_routing para los usuarios. URL pública del manifest: Cloud Storage → Configuración → URL pública del portal.

Portal de estudios: esta pestaña prepara el enrutamiento unificado (Local / Remoto / R2) para paciente.html.

Importante: mientras portal_estudios_v2_enabled esté en No, el portal mantiene el comportamiento legacy actual sin cambios.

Auto-vinculación por score: cuando está activada, al recibir un informe por API se calcula un score de coincidencia y se vincula automáticamente si supera el umbral configurado.

Auto envío a PACS: si lo activa en la lista inferior, después de vincular el informe recibido (por API con vinculación automática o manual desde el gestor) el sistema intentará enviar el PDF del informe a Orthanc con la misma lógica que el botón de envío a PACS. Si falla Orthanc o la red, la vinculación no se deshace; el error quedará registrado en el log del servidor.

Carpetas PDF/TXT (SMB): al final de esta pestaña, ic_pdf_path e ic_txt_path definen las rutas Linux donde están montados los recursos Windows (valores sugeridos por defecto: /var/www/tjsiddse/uploads/informespdf_net y /var/www/tjsiddse/uploads/mensajesris_net). El servicio workers/watch-informes-carpeta.sh vigila esas rutas y registra la cola en base de datos.

Si el informe objetivo ya está en PACS y la política es bloquear, el recibido quedará pendiente con motivo de actualización bloqueada hasta quitar primero la versión anterior de PACS.

SLA de publicación: el reloj arranca cuando el estudio aparece en el PACS local (Orthanc). El cumplimiento es el informe publicado en PACS. Por defecto la función está apagada (sla_activo=0) para no afectar a usuarios hasta activarla.

Plantillas por modalidad y el snippet Lua para Orthanc OnStableStudy están debajo de los campos. Permiso de monitoreo en informes-manager: monitorearSlaEstudios.

Configuración de Ollama para acceso por LAN/WAN

                        
Por defecto, Ollama solo escucha en localhost (127.0.0.1). Para permitir acceso desde otras máquinas en la red, necesitas configurar la variable de entorno OLLAMA_HOST:

                        

                            Opción 1 (Recomendada): Escuchar en todas las interfaces

                            export OLLAMA_HOST=0.0.0.0:11434


                            Opción 2: Escuchar en IP específica de la LAN

                            export OLLAMA_HOST=192.168.0.33:11434


                            Para hacer permanente: Agregar al archivo ~/.bashrc o crear servicio systemd
                        

                        
Después de configurar, reinicia Ollama: systemctl restart ollama o pkill ollama && ollama serve
